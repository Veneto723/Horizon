## [YC 发布面向工作的多人代理框架 QM](https://github.com/yc-software/qm) ⭐️ 10.0/10

YC Software 发布了 QM，这是一个开源的“面向工作的多人代理框架”，可在 Slack 和网页端使用。该项目面向初创团队工作流，提供每位员工独立的隔离工作区，同时支持在频道、群组消息和项目中与代理协作。 这把代理产品从单用户助手推进到共享团队工作流，而很多真实的商业场景正发生在这里。若 QM 按描述运行良好，它可能成为企业如何在一个系统里协调人类、代理和现有办公工具的参考范例。 GitHub 介绍写明 QM 面向初创团队，并强调隔离性，让员工可以彼此独立工作而不互相干扰。评论区还提到更广泛的互操作性需求，有人希望它支持其他代理和 MCP 客户端，以便适配更多渠道和工具。

hackernews · tosh · 7月31日 18:04 · [社区讨论](https://news.ycombinator.com/item?id=49126604)

**背景**: “多人代理框架”指的是让多人和 AI 代理共享同一工作环境的系统，而不是只停留在单人私聊助手。之所以重要，是因为办公场景中的代理需要权限范围、共享房间和协作规则，而不只是一个响应提示词的循环。文中提到的 MCP，即 Model Context Protocol，通常用于把代理连接到外部工具和数据源。

## [MCP 2.0 转向无状态](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 10.0/10

Simon Willison 表示，2026-07-28 的 MCP 规格发布，也就是 MCP 2.0 和“无状态 MCP”，是该协议自推出以来最重要的一次变化。他说，这一设计重新激发了他围绕 MCP 开发的兴趣，并促使他做出了 mcp-explorer 和 datasette-mcp 等工具。 MCP 是向 LLM 代理暴露工具的核心协议，因此把它改成无状态可以降低实现复杂度，也更容易扩展部署。这对构建代理基础设施的人很重要，因为它减少了服务端状态管理，并提升了与普通 HTTP 路由的兼容性。 文章对比了旧版 MCP：它需要先初始化会话并获取会话 ID，再发起工具调用；而新的无状态流程可以用一次 HTTP 请求完成工具调用。Willison 还认为，与给代理一个可联网的 shell 相比，MCP 工具更容易审计和控制，尤其适合较小的模型。

rss · Simon Willison · 7月31日 23:13

**背景**: MCP 是 Model Context Protocol 的缩写，是一种开放标准，用于让应用向 LLM 和代理框架提供工具与上下文。Anthropic 在 2024 年 11 月推出了它，2025 年曾引发很大关注，之后又被 Claude Skills 等方案分走了一部分注意力。2026-07-28 规格把协议推进到传输层无状态化，这也更适合标准 Web 基础设施。

## [datasette-agent 0.4a0 增加浏览器执行任务](https://simonwillison.net/2026/Jul/31/datasette-agent/#atom-everything) ⭐️ 9.0/10

datasette-agent 0.4a0 引入了新的 `await context.browser_task()` API。它允许代理工具和插件直接在用户的浏览器中运行自定义 JavaScript。 这把 Datasette Agent 插件的能力从仅限服务器端工具调用，扩展到可以做浏览器原生自动化和界面交互。对于构建代理产品的人来说，这为需要访问实时浏览器会话的任务提供了更强的集成方式。 这次发布说明把该特性关联到拉取请求 #33，并将其描述为让插件在用户浏览器中执行 JavaScript 的方式。现有内容没有说明权限模型、沙箱细节或浏览器支持范围。

rss · Simon Willison · 7月31日 14:14

**背景**: Datasette 是一个用于探索和发布数据的开源工具，而 Datasette Agent 是它的 LLM 驱动助手层。代理工具是扩展点，允许插件添加助手可以代表用户执行的动作。浏览器执行任务的 API 之所以重要，是因为有些工作流需要与只存在于用户自己浏览器会话中的页面状态交互。
